# Codex Matt Pocock Adapter

本技能补充 Matt Pocock 的工程技能；原技能的任务流程继续适用。仅在对应原技能已经安装并进入相关流程时应用以下规则。正文中的委派要求以 Codex 提供 `collaboration` 工具为前提。

## 适用范围

- 执行 `implement` 时，应用强制委派实现规则，包括已有 tickets 和没有 tickets 的实现任务。
- 执行 `code-review` 时，应用强制双代理审查规则，包括独立审查和实现后的审查。
- `research`、`grilling`、`improve-codebase-architecture`、`codebase-design` 和 `wayfinder` 进入委派步骤时，应用“其他技能的委派”规则。
- 其他技能或未进入上述步骤的流程继续按原技能执行，不因加载本适配器而额外创建子代理。

## implement：强制委派实现

- 输入已有 tickets 时，每张 ticket 使用 `collaboration.spawn_agent` 创建一个全新的专属实现子代理。只有阻塞项完成后，才能启动依赖它们的 ticket。
- 输入是 spec 或已明确的任务、没有 tickets 时，为本次实现创建一个全新的实现子代理，无须为了委派创建 ticket。若任务过大、需要拆分，先按 `to-tickets` 确认拆分，再逐 ticket 委派；不得把大型 spec 自动视为一个小任务。
- 实现代理使用 `fork_turns="none"`。父代理提供自包含任务材料：ticket 或 spec、验收条件、已确认的设计决定与理由、测试边界、适用的项目指令及相关来源。没有正式 spec 时，传递已确认的原始需求和必要讨论内容，不能只提供模糊摘要。
- 一个实现子代理只负责一张 ticket 或一次没有 ticket 的实现任务，绝不复用于其他任务。同一任务的补充或修正交回原子代理；仅当它不可恢复时，允许创建新的替代代理，并交接已完成工作、验证结果和剩余事项。
- 父代理只负责编排：提供任务材料、协调依赖、记录审查基准、收集结果、组织审查和向用户汇报。实现、代码修改、测试及原技能要求的提交由实现子代理执行。
- 默认按依赖顺序串行实现。并行实现前须隔离工作区及分支，明确集成责任，避免共享工作区中的改动和提交相互混入。
- 实现子代理完成代码与测试后，将结果交回父代理。由父代理启动 code-review，随后把需要修正的问题交回原实现代理，完成后再按原流程提交。子代理不再次启动 implement 编排，也不另建一组审查代理。

## code-review：强制双代理审查

- 先确认比较基准有效且目标改动非空，再进入审查。无效基准或空改动应按原技能提前停止，不创建审查代理。
- 实现任务开始前记录基准提交及已有工作区改动。实现完成、提交之前的审查须覆盖本任务的已提交、暂存、未暂存和新增文件；不得仅使用 `git diff <fixed-point>...HEAD`，也不得把已有无关改动算入本任务。独立审查已提交分支时继续使用原技能的比较方式。
- 为两个审查代理提供同一份稳定的目标快照、比较基准和可复现的差异读取方式。审查期间暂停修改目标；若内容发生变化，应重新确定范围，旧报告不代表新内容已经通过审查。
- 每轮有效审查使用 `collaboration.spawn_agent` 恰好创建两个全新的审查子代理，并行执行：一个负责 Standards，一个负责 Spec。它们就是原技能要求的审查代理，不额外创建另一组，也不复用实现代理或以前的审查代理。修正后若开启新一轮审查，再创建两个新的审查代理。
- 两次创建均设置 `fork_turns="none"`，分别提供完成各自审查所需的材料：共同的目标快照、比较基准、差异读取方式和适用的提交列表；Standards 接收标准来源和原技能的完整 smell baseline，Spec 接收需求来源或内容。任务本身已确认的需求可以作为 Spec 来源，无须另建 spec 文件。
- 两个审查子代理独立开展审查，不互传发现，不接收父代理或实现代理的预先结论，也不继续委派审查。父代理在两份报告完成后分别汇总结果。
- 按原技能查找和澄清需求来源后，若确认缺少 spec 或其他明确需求，仍须创建 Spec 子代理，由它报告“缺少需求依据，无法评估需求符合性”，不得推测需求或报告通过。此规则替代原技能中跳过 Spec 子代理的分支。

## 其他技能的委派

- 保留 `research` 的后台研究、`grilling` 的事实调查、`improve-codebase-architecture` 的代码扫描，以及 `codebase-design` 在探索替代接口时要求的至少三个独立并行设计代理。仅查询设计词汇不触发设计代理。
- 已被明确派为执行者的子代理直接完成分配工作，不因加载同一技能再次委派同一任务。尤其在 `wayfinder` 派发研究 ticket 后，研究代理直接执行 `research` 的调查与记录步骤，避免重复嵌套委派。
- 独立设计代理使用 `fork_turns="none"`，接收共同的事实材料和各自不同的设计约束，在结果完成前不互传方案。
- 父代理统一收集需要用户决定的问题，并传递已经确认的答案和授权；子代理不重复询问已有结论。其他技能的父代理职责仍按原技能执行，implement 的“只编排”限制不扩展到所有技能。

容量暂时不足时，等待现有工作完成再安排委派，不得因此改由父代理实现或审查。若工具不可用或容量限制使规定的并行执行无法实现，应说明具体受阻条件，不得声称已满足强制委派要求。
